## 2. Context

v0.1.0 shipped the smallest possible chat UI: a top bar plus a full-viewport `CopilotChat`. v0.2.0 adds a second view (ETF Grid) and later milestones add more, so the shell is extracted now, while there is still exactly one view. The sidebar's information architecture and visual direction were settled through design-mockup review (`docs/design/v0.1.1-app-shell-mockup.html`, ChatGPT-style layout as the structural reference — not its colors).

Key constraints and decisions:

- **Component library: shadcn/ui** (owner decision — no hand-rolled UI controls for non-chat areas). Components are vendored into `src/components/ui/` per shadcn's distribution model; behavior comes from npm-installed Radix UI primitives. Icons: `lucide-react`.
- **One theme system**: shadcn/ui and CopilotKit v2 both read the same shadcn-style semantic CSS variables (`--background`, `--primary`, `--card`, `--sidebar-*`, …), so a single token file themes the shell and the chat surface together.
- **Palette: official defaults, no custom colors** (owner decision — no time on bespoke palettes now). Base color **Neutral**; both `:root` (light) and `.dark` token sets are defined per the official scaffold; **dark is the default** (`.dark` on the root element). A light/dark toggle is deferred.
- **Sidebar structure** (owner-reviewed):
  - *Upper part*: 新聊天 (functional), 定时任务 (disabled placeholder — future automation milestone, Runtime ADR 0003), 插件 (expandable group; children registered per Runtime extension — currently a disabled "ETF 网格" placeholder for v0.2.0).
  - *Lower part*: 最近 conversations. The current thread is the highlighted entry here; a real history list belongs to the future thread-management milestone, so only the current-conversation entry is real.
  - *Bottom*: user area (avatar + static display name) — a placeholder slot; no auth in the single-user phase (Runtime ADR 0005).
- **Minimalism holds**: no router library; the active view is local React state. Chat behavior (`thread_id` persistence, "new conversation" reset, `CopilotKit` provider) is unchanged — only its placement in the layout changes.
- **Desktop-first**: sidebar collapse comes free with the shadcn Sidebar primitives; narrow-screen/drawer adaptation is deferred.

Stack changes: add shadcn/ui (vendored components + Radix primitives) and `lucide-react`. Everything else unchanged.

## 3. Scope

### 3.1 In Scope

1. **shadcn/ui project setup**
   - Init shadcn/ui for the Vite + React 19 + Tailwind 4 stack (path alias `@/`, `components.json`), vendored under `src/components/ui/`.
   - Global CSS with the official **Neutral** token set in `:root` and `.dark`; root element defaults to dark mode; CopilotKit's container picks up the same tokens (`.dark` applies to `[data-copilotkit]`).

2. **App shell with sidebar** (built from shadcn/ui Sidebar primitives)
   - Full-height layout: sidebar + main content area rendering the active view.
   - **Brand row**: "Spectres" wordmark; sidebar collapse via the library's trigger.
   - **Upper nav**: 新聊天 (resets the conversation — the existing `resetThreadId` behavior), 定时任务 (disabled), 插件 expandable group containing a disabled ETF 网格 entry. Data-driven: entries and plugin children come from typed lists.
   - **Lower nav**: 最近 group with the current conversation as the single real, highlighted entry (clicking returns to the chat view).
   - **User area** at the bottom: avatar + static display name ("Dong-xu Gu", subtitle 本地单用户), visually separated.

3. **Chat integration**
   - `ChatPage` renders in the main area, functionally unchanged (streaming, thread persistence).
   - Chat surface follows the shared theme tokens (dark), replacing the old top bar entirely.

4. **Docs & versioning**
   - Update `docs/frontend-architecture.md` (app shell layer, shadcn/ui adoption, theme token convention, nav/plugin registration convention).
   - Update `AGENTS.md` §3.2 milestone status, §3.3, and §5 tech-stack table.
   - Bump `package.json` version to `0.1.1`.

### 3.2 Out of Scope

- **Custom color palettes / accent colors** — official Neutral defaults only; bespoke branding deferred.
- **Light/dark toggle UI** — both token sets are defined, but the switcher is a later nicety.
- **Router library / deep-linking** — deferred until a milestone forces it.
- **Real conversation history list** — thread-management milestone; only the current-conversation entry is real.
- **定时任务 and ETF 网格 functionality** — placeholders only (automation milestone and v0.2.0 respectively).
- **Real user identity / auth** — single-user phase (Runtime ADR 0005).
- **Narrow-screen / mobile adaptation** — desktop-first.
- **Tests** — manual verification per milestone walkthrough, as before.
