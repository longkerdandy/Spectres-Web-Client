## 2. Context

The Runtime now requires a Bearer JWT on every endpoint except `/health` (Runtime ADR 0009, self-hosted Logto OSS on `http://localhost:3001`). Without a token the Runtime returns 401. This milestone makes the client a Logto SPA application:

- **Fixed integration parameters** (registered in Logto, not configurable here):
  - SPA App ID: `20vb1euxbpw6m8nqdgkxs`
  - Redirect URI: `http://localhost:3000/callback` (Vite dev server port 3000)
  - Post-sign-out redirect URI: `http://localhost:3000`
  - API resource indicator (audience): `https://spectres.runtime/api` — the Runtime only accepts JWT access tokens issued for this resource; without it Logto returns an opaque token the Runtime rejects.
- **Token lifecycle**: Logto access tokens expire after 1h; `getAccessToken(resource)` refreshes transparently via the refresh token. Tokens are stored by the SDK only — never hand-rolled into `localStorage`.
- **No router**: the `/callback` route is handled by a pathname check at the entry point, not by adding a router library.
- **Token injection mechanism**: `@ag-ui/client`'s `HttpAgentConfig` accepts a custom `fetch` function, invoked per request (`run()` calls `this.fetch(this.url, this.requestInit(input))`). The agent's `headers` are cloned at construction, so the custom-fetch hook is used to attach a fresh token per request — one agent per thread is preserved, no `CopilotKit` remount, no lost chat state.

## 3. Scope

### 3.1 In Scope

1. **Auth module** (`src/auth.ts`): env-driven Logto config (`VITE_LOGTO_ENDPOINT`, `VITE_LOGTO_APP_ID`, `VITE_LOGTO_API_RESOURCE`, with localhost defaults), the `LogtoConfig` object, and module-level auth plumbing (token getter + re-auth handler registration) usable outside React.
2. **Provider & gate**: `LogtoProvider` in `main.tsx`; an auth gate that renders a loading state while the SDK initializes, a minimal login screen (single Sign in button) when unauthenticated, the sign-in callback handler at `/callback` (via `useHandleSignInCallback`, then back to `/`), and the existing app when authenticated.
3. **Token injection — chat (AG-UI)**: custom `fetch` on the `HttpAgent` that awaits a fresh `getAccessToken(apiResource)` per request and sets the `Authorization` header; on repeated token failure the registered re-auth handler (a `signIn` redirect) fires.
4. **Token injection — ETF Grid REST**: the plugin's `request()` wrapper attaches the same Bearer token; a 401 response triggers the same re-auth handler.
5. **Sign out**: shell user area shows the signed-in user's name (from `getIdTokenClaims()`) and a sign-out button calling `signOut(postLogoutRedirectUri)`.
6. **Docs & versioning**
   - `.env.example` + README: document the three new `VITE_LOGTO_*` variables.
   - `docs/frontend-architecture.md`: new Authentication section.
   - `AGENTS.md` §3.2: current milestone → v0.3.0; §3.3: drop the "authentication deferred" bullet (multi-tenancy stays deferred).
   - Bump `package.json` version to `0.3.0`.

### 3.2 Out of Scope

- **Multi-tenancy / user switching UI** — still deferred; first implementation targets the single-user scenario.
- **Role/permission-based UI** (hiding features by scope) — the Runtime enforces; the client only authenticates.
- **Router library / deep-linking** — the `/callback` pathname check stays a deliberate minimalism.
- **Tests** — manual verification per walkthrough, as in previous milestones.
- **Any Runtime-side change** — Logto registration, JWKS, and validation are done (ADR 0009).

## 4. Success Criteria

- [ ] Opening the app unauthenticated shows the login screen; Sign in redirects to the Logto hosted page.
- [ ] After signing in on the Logto page, the browser returns to the app and lands on the chat.
- [ ] Chat messages stream (AG-UI requests carry a valid JWT Bearer token; no 401s).
- [ ] The ETF Grid page loads data (extension REST calls carry the token; no 401s).
- [ ] Sign out returns to the login screen (via Logto's end-session redirect).
- [ ] After an hour (or with an expired token), the next request refreshes the token transparently — no manual re-login.
- [ ] `npm run lint`, `npm run typecheck`, and `npm run build` pass.

## 7. Manual Verification (owner walkthrough)

Prerequisites:

1. In the Runtime repo, start Logto + its database: `docker compose up -d` (Logto on `http://localhost:3001`).
2. Start the Runtime on `http://localhost:7777` (auth enforced).
3. Start this app: `npm run dev` (port 3000).

Walkthrough:

1. Open `http://localhost:3000` in a browser with a clean session (or signed out) → the login screen appears (app name + Sign in button).
2. Click **Sign in** → redirected to the Logto hosted sign-in page at `http://localhost:3001` → sign in with the test account.
3. Browser returns to `http://localhost:3000/callback`, then lands on the chat view; the sidebar user area shows the account's name.
4. Send a chat message → the reply streams (DevTools: the `POST /agui` request carries `Authorization: Bearer <jwt>`).
5. Open the ETF Grid page from the sidebar → status table and ledger load (DevTools: requests to `/api/v1/extensions/etf-grid/*` carry the Bearer token).
6. Click the sign-out button in the sidebar user area → redirected through Logto's end-session → back at the app's login screen.
7. (Optional) After the access token's 1h lifetime, send another message → it succeeds without re-login (silent refresh via the refresh token).
