## 2. Context

Two open Dependabot PRs are blocked on this upgrade:

- **#3** (`@ag-ui/client` 0.0.59 → 1.0.2 alone) fails CI: `src/app.tsx` `TS2418 — HttpAgent not assignable to AbstractAgent`.
- **#10** (patch/minor group incl. `@copilotkit/react-core` 1.77.0) fails CI with the same error.

**Root cause** (verified against the AG-UI source and npm metadata): `AbstractAgent` declares `private` fields, so TypeScript assignability is *nominal* — an `HttpAgent` and an `AbstractAgent` slot only type-check when both come from the **same installed copy** of `@ag-ui/client`. `@copilotkit/react-core` pins `@ag-ui/client` as an **exact** dependency (1.73.0 → `0.0.59`, 1.76.0 → `1.0.1`, 1.77.1+ → `1.0.2`). Bumping either side alone installs two copies and breaks the `selfManagedAgents` typing in `src/app.tsx:28`. CopilotKit moved onto AG-UI 1.0 in [v1.76.0](https://github.com/CopilotKit/CopilotKit/releases/tag/v1.76.0) ([PR #7270](https://github.com/CopilotKit/CopilotKit/pull/7270)), so the fix is to upgrade both in one commit.

**AG-UI 1.0 changes** (from the [migration guide](https://docs.ag-ui.com/migrating-to-1-0), [client CHANGELOG](https://github.com/ag-ui-protocol/ag-ui/blob/main/sdks/typescript/packages/client/CHANGELOG.md), and [spec changelog](https://docs.ag-ui.com/spec/1.0/changelog)):

- **Our only touchpoint is unchanged**: `new HttpAgent({ url, threadId })` in `src/ag-ui.ts` is still valid in 1.0.2; `AgentConfig`, `runAgent`, and the `AbstractAgent` surface CopilotKit consumes are compatible.
- **0.x producers keep working**: an always-on compatibility boundary translates legacy stream shapes (`THINKING_*` → `REASONING_*`, optional `null` fields, binary parts) with console warnings — so the current Agno `/agui` endpoint remains usable. 1.0.2 widened `null` tolerance further.
- **Stricter enforcement**: unknown event types are dropped, unknown properties stripped, malformed known values fail the run; stream buffers are capped. Anything non-standard Agno emits becomes visible (warning or failure) instead of silently passing through.
- **Protocol handshake**: requests now carry `protocolVersion: "1.0"`; a pre-1.0 peer simply doesn't answer it — harmless.
- **zod split**: validators moved to `@ag-ui/core/schemas`; we import no validators, so nothing changes for us.
- **New capabilities for later milestones** (not adopted here): `REASONING_*` events, run outcomes & **interrupts** (human-in-the-loop, `pendingInterrupts`), `SUBAGENT_*` events (matches Runtime ADR 0004 per-Slave visibility), `ACTIVITY_*` messages, per-run token `usage`.

**CopilotKit 1.73.0 → 1.77.2 changes relevant to this app** (from the [release notes](https://github.com/CopilotKit/CopilotKit/releases)):

| Version | Change | Impact |
|---------|--------|--------|
| 1.74.0 | fix(react-core): stop per-message state cloning and the virtual-scroll tug of war (#7243) | Chat rendering perf; take it for free |
| 1.75.0 | feat(react-core): `transformMessages` on `CopilotChatMessageView` (#7488); **requires `@tanstack/react-virtual` `^3.14.13`** | Dependency floor — `npm install` handles it; `transformMessages` not adopted (out of scope) |
| 1.75.2 | fix(react-core): new run IDs for standard interrupt resumes (#7001) | Groundwork for future HITL; no action |
| 1.76.0 | feat: AG-UI 1.0 for CopilotKit (#7270); tool results convert supported content to readable text; finish reasons/usage preserved in metadata | The pairing constraint; behavior change in tool-result rendering to verify |
| 1.77.0 | feat(react-core): `showIntelligenceIndicator` provider prop, **defaults to `true`** (#6612); fix(core): pass `ContentPart[]` tool handler results through (#7544) | **Action required**: we have no CopilotKit Cloud/Intelligence — opt out explicitly |
| 1.77.1 | feat(react-core): `groupMessages` on `CopilotChatMessageView` (#7650); fix(react-core): **wait for thread replay before sending prompts** (#7657); fix useCoAgent via v2 core (#7610); chore: `@ag-ui/*` → 1.0.2 | Thread-replay fix directly benefits our `localStorage` `thread_id` resume flow; `groupMessages` not adopted (out of scope) |
| 1.77.2 | Runtime-only feature | None |

Versions 1.74–1.77 also ship web-inspector HUD / "What's New" / onboarding features (#6956, #7376, #7542, #7667). We run fully self-managed with no CopilotKit Cloud credentials; the walkthrough must confirm none of this UI mounts (and disable it if it does).

Key constraints and decisions:

- **Paired, pinned upgrade**: `@copilotkit/react-core` goes to `^1.77.2`; `@ag-ui/client` is pinned to the **exact** version CopilotKit 1.77.2 pins (`1.0.2`), no caret — a caret lets a future `@ag-ui/client` patch resolve ahead of CopilotKit's pin, recreating the dual-copy breakage. This convention is documented in `docs/frontend-architecture.md`.
- **No new feature adoption**: reasoning UI, interrupts, subagent events, `transformMessages`, `groupMessages` are deliberately deferred — this milestone is an upgrade plus *necessary* adjustments, not a feature milestone. The upgrade unblocks them.
- **Dependabot solo bumps are expected and handled manually**: Dependabot will keep proposing `@ag-ui/client` (or CopilotKit) updates that break the pairing; such PRs are treated as upstream-release notifications — closed in favor of a paired manual upgrade, not merged. The Dependabot config is deliberately left unchanged (owner decision: keep the notifications).

## 3. Scope

### 3.1 In Scope

1. **Paired dependency upgrade**
   - `@copilotkit/react-core` `^1.73.0` → `^1.77.2`; `@ag-ui/client` `^0.0.59` → `1.0.2` (exact).
   - Verify with `npm ls @ag-ui/client` that the whole tree dedupes to a single copy.
   - Verify `@tanstack/react-virtual` resolves ≥ 3.14.13 (1.75.0 upgrade note).

2. **Code adaptation** (expected to be minimal — the point of the paired upgrade)
   - `src/ag-ui.ts`: no change expected; confirm `HttpAgent({ url, threadId })` compiles against 1.0.2.
   - `src/pages/chat-page.tsx`: the `LABEL_KEYS … satisfies readonly (keyof CopilotChatLabels)[]` guard fails loudly if 1.77 renamed any label key — fix if so. Confirm `useDefaultRenderTool` and `CopilotChat` are still exported from `@copilotkit/react-core/v2`.
   - `src/app.tsx`: add `showIntelligenceIndicator={false}` to the `CopilotKit` provider (we have no CopilotKit Cloud/Intelligence backend; the indicator has nothing to report).

3. **Release-note-driven UI/behavior verification** (browser, against the real Runtime)
   - No Intelligence indicator, web-inspector HUD, or "What's New" UI appears in the self-managed setup.
   - Thread resume: reload with a persisted `thread_id`, confirm history replays before a new prompt can be sent (1.77.1 #7657), and the agent answers in context.
   - Tool calls still render via the generic renderer; tool results containing content parts render as readable text (1.76.0 behavior).
   - Long conversation scrolls without the pre-1.74 virtual-scroll twitch.
   - Browser console: identify and document the expected compatibility-boundary warnings from Agno's 0.x stream (e.g. legacy `null` fields); confirm nothing *fails* the run.

4. **Dependabot PR cleanup** (no config change — solo-bump PRs stay enabled as upstream notifications)
   - Dependabot PRs #3 and #10 are closed as superseded after this milestone merges; future solo `@ag-ui/client`/CopilotKit PRs that break the pairing are handled the same way.

5. **Docs & versioning**
   - `docs/frontend-architecture.md`: the `@ag-ui/client` = CopilotKit-pin convention (why exact, how to bump), and an "AG-UI 1.0 behavior notes" paragraph (enforcement strictness, compatibility-boundary warnings, `protocolVersion`).
   - `AGENTS.md` §3.2 milestone status.
   - Bump `package.json` version to `0.1.4`.

### 3.2 Out of Scope

- **Adopting AG-UI 1.0 features**: reasoning display, interrupt/HITL UI, subagent visibility, activity messages, token-usage display — each lands in a later milestone with concrete requirements (Runtime ADR 0004 governs subagent visibility).
- **`transformMessages` / `groupMessages`** adoption — evaluated when a chat-UI milestone needs them.
- **Runtime-side producer upgrade** (Agno emitting native 1.0 shapes) — the Runtime project's decision; the client's compatibility boundary covers the interim.
- **`@ag-ui/core/schemas` / zod validators** — we validate nothing client-side.
- **CopilotKit web-inspector / Intelligence / Cloud features** — excluded by project principle (AGENTS.md §4.2); only verified absent.
