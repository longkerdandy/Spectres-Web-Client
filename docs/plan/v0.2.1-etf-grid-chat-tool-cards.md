## 2. Context

[v0.2.0](v0.2.0-etf-grid-frontend.md) delivers the standalone ETF Grid page (REST-driven). This follow-up milestone implements the second half of the Runtime's Client contract (`runtime-extensions.md` §7): **in-chat** custom renderers registered by stable tool name via CopilotKit's `useRenderTool`.

Key constraints and decisions:

- **Depends on v0.2.0**: reuses the TypeScript types and presentation/formatting helpers introduced there; the standalone page's status table is the visual reference for the cards.
- **AG-UI only**: cards consume the standard AG-UI `TOOL_CALL_*` stream; there are no `etf_grid`-specific AG-UI events or state snapshots to handle (Runtime ADR 0004, phase 1). Tool names are stable by contract (`runtime-extensions.md` §6.3) — that stability is what makes name-matched renderers safe.
- **Chat thread continuity**: registering renderers must not change `thread_id` handling or the `CopilotKit` provider setup.
- **No HITL yet**: `record_grid_trade` executes immediately Runtime-side; the trade receipt card only *echoes* the computed amounts for in-dialog verification — it is not a confirmation gate.
- **Data shapes**: as in v0.2.0 — Decimal values are strings, dates are ISO strings; reuse the existing formatting helpers, never float math on money.

## 3. Scope

### 3.1 In Scope

1. **Tool card components** (registered via `useRenderTool`, matched by stable tool name)
   - `get_grid_status` → status card: per-symbol holdings, latest close/market value, level vs. anchor, latest signal's limit-order list, gate state — a compact version of the v0.2.0 status table.
   - `refresh_grid_data` → pipeline result card: rows synced per source, recomputed signals, per-source `errors` surfaced as warnings.
   - `record_grid_trade` → trade receipt card: echoed gross/commission/net for in-dialog verification.
   - `list_grid_trades` → recent-trades card: compact table of the latest N trades.
2. **Streaming states**: in-progress tool-call indicator and error/exception rendering for each card.
3. **Fallback integrity**: the generic renderer remains the fallback for all other tools (current `useDefaultRenderTool` behavior is preserved).
4. **Docs & versioning**
   - Update `docs/frontend-architecture.md` (tool-card registration layer).
   - Update `AGENTS.md` §3.2 milestone status.
   - Bump `package.json` version to `0.2.1`.

### 3.2 Out of Scope

- **HITL confirmation UX** for `record_grid_trade` — deferred until the Runtime adopts Agno `requires_confirmation` (shared HITL path, Runtime ADR 0003 / architecture §6).
- **Any change to the standalone Grid page** beyond sharing types/helpers — page evolution is a later milestone.
- **Per-Slave visibility and custom AG-UI events** — Runtime ADR 0004 phase 2+.
- **Proactive notifications** — later automation milestone (Runtime ADR 0003).
- **Tests** — manual verification per walkthrough, as in previous milestones.

## 4. Success Criteria

- [ ] In a live chat, each of the four grid tools renders its custom card with correct data.
- [ ] While a tool call is in flight, an in-progress state is shown; tool errors render readably.
- [ ] `refresh_grid_data` partial failures (per-source `errors`) appear as warnings on the pipeline card.
- [ ] Unregistered tools still fall back to the generic renderer.
- [ ] Switching between Chat and Grid views still does not reset the chat thread.
- [ ] `npm run lint` and `npm run typecheck` pass.
