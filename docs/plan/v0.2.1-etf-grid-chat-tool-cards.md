## 2. Context

[v0.2.0](v0.2.0-etf-grid-frontend.md) delivers the standalone ETF Grid page (REST-driven). This follow-up milestone implements the second half of the Runtime's Client contract (`runtime-extensions.md` §7): **in-chat** custom renderers registered by stable tool name via CopilotKit's `useRenderTool`.

Key constraints and decisions:

- **Depends on v0.2.0**: reuses the presentation/formatting helpers introduced there; the standalone page's status table is the visual reference for the cards.
- **AG-UI only**: cards consume the standard AG-UI `TOOL_CALL_*` stream; there are no `etf_grid`-specific AG-UI events or state snapshots to handle (Runtime ADR 0004, phase 1). Tool names are stable by contract (`runtime-extensions.md` §6.3) — that stability is what makes name-matched renderers safe.
- **CopilotKit v2 API**: `useRenderTool` / `useDefaultRenderTool` are v2-entry exports — import from `@copilotkit/react-core/v2` (as `src/pages/chat-page.tsx` already does). Named renderers must supply `parameters` as a Standard Schema V1 schema (zod, added as an explicit dependency — it is already in CopilotKit's dependency tree). Render props are `{ name, toolCallId, parameters, status, result }` with `status ∈ {inProgress, executing, complete}`: `parameters` is `Partial` while `inProgress`, and `result` (a string) exists only at `complete`.
- **Tool result envelope**: since Runtime v0.4.2, every tool returns `{"ok": true, "data": ...}` or `{"ok": false, "error": {"type", "message", "trace_id", "hint"}}` — tools never raise across the boundary (`runtime-extensions.md` §6.5). Cards parse the JSON `result`, unwrap `data`, and render the structured `error` (including the `hint`/`trace_id` self-diagnosis line) on failure.
- **Tool shapes ≠ REST shapes**: the v0.4.4 pagination envelope (`{"items", "total", ...}`) is REST-only; tools return bare objects/arrays (`list_grid_trades` truncates silently at `limit`). Card types are defined per tool response — the v0.2.0 REST paginated types are not reused for tool results.
- **Chat thread continuity**: registering renderers must not change `thread_id` handling or the `CopilotKit` provider setup.
- **No HITL yet**: `record_grid_trade` executes immediately Runtime-side; the trade receipt card only *echoes* the computed amounts for in-dialog verification — it is not a confirmation gate.
- **Data shapes**: as in v0.2.0 — Decimal values are strings, dates are ISO strings; reuse the existing formatting helpers, never float math on money. `get_grid_status` rows additionally carry `unrealized` / `unrealized_percent` since Runtime v0.4.5 (stringified Decimals, `null` when underivable).

## 3. Scope

### 3.1 In Scope

1. **Tool card components** (registered via `useRenderTool` from `@copilotkit/react-core/v2`, matched by stable tool name; one zod `parameters` schema per tool)
   - `get_grid_status` → status card: per-symbol holdings, latest close/market value, realized + unrealized P&L (`unrealized` / `unrealized_percent`, `null`-aware), level vs. anchor, latest signal's limit-order list, gate state — a compact version of the v0.2.0 status table.
   - `refresh_grid_data` → pipeline result card: rows synced per source, recomputed signals, per-source `errors` surfaced as warnings.
   - `record_grid_trade` → trade receipt card: echoed gross/commission/net for in-dialog verification.
   - `list_grid_trades` → recent-trades card: compact table of the latest N trades (bare array, no pagination envelope).
2. **Result-envelope handling**: a shared helper parses the JSON `result` string, unwraps `{ok: true, data}` into each card's typed payload, and maps `{ok: false, error}` to a readable error card showing `message`, `type`, and the `hint`/`trace_id` lookup line.
3. **Streaming states**: in-progress tool-call indicator (`status: "inProgress" | "executing"`) and structured-error rendering for each card.
4. **Fallback integrity**: the generic renderer remains the fallback for all other tools (current `useDefaultRenderTool` behavior is preserved; named renderers take precedence over its `"*"` wildcard).
5. **Docs & versioning**
   - Update `docs/frontend-architecture.md` (tool-card registration layer).
   - Update `AGENTS.md` §3.2 milestone status.
   - Bump `package.json` version to `0.2.1`.

### 3.2 Out of Scope

- **HITL confirmation UX** for `record_grid_trade` — deferred until the Runtime adopts Agno `requires_confirmation` (shared HITL path, Runtime ADR 0003 / architecture §6).
- **Any change to the standalone Grid page** beyond sharing types/helpers — page evolution is a later milestone.
- **Per-Slave visibility and custom AG-UI events** — Runtime ADR 0004 phase 2+.
- **Proactive notifications** — later automation milestone (Runtime ADR 0003).
- **Tests** — manual verification per walkthrough, as in previous milestones.

- [x] In a live chat, each of the four grid tools renders its custom card with correct data.
- [x] The status card shows realized + unrealized P&L consistent with the standalone Grid page.
- [x] While a tool call is in flight, an in-progress state is shown; tool failures returned as `{ok: false, error}` render readably with the `hint`/`trace_id` lookup line.
- [x] `refresh_grid_data` partial failures (per-source `errors`) appear as warnings on the pipeline card.
- [x] Unregistered tools still fall back to the generic renderer.

- [x] `npm run lint` and `npm run typecheck` pass.
